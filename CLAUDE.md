## The game

**Ascendant Impact** — a one-versus-one cyber-fantasy martial-arts duel in **Unreal
Engine 5.8**, PC, third person, **Blueprint-only** (no `Source/`, and no C++ toolchain on
this machine). The player fights **Crimson Vanguard** in an octagonal industrial arena.

The Unreal project is at **`game/AscendantImpact.uproject`** and it is the only copy.

**What works today:** player movement, jump-over with side switching, punch, health,
hit-react, camera shake, ragdoll death · a Vanguard with range-band AI movement,
directional locomotion, and one telegraphed strike that is interruptible and dodgeable ·
a 2.5D duel camera with mutual facing and arena bounds ±650 · a duel HUD with both health
bars · a knockout coordinator · and a full octagon arena, generated by
`game/Tools/ArenaPipeline/` and merged into the duel level.

**What is missing** is the four problems in `FINISH-PLAN.md`: you cannot win, you cannot
lose, backing up beats the Vanguard every time, and he has only one attack.

## Scope — this is a hard wall

One player, one authored opponent, one arena, one match with a win and a loss.

**Explicitly not being built, and no agent may start one:** the Ascension Meter, Impact
Windows, the Final Clash, Phase 2 rival behaviour, dodge/counter scoring, a second
playable character, a second arena, more than three Vanguard attacks, multiplayer,
progression, or story. These were deferred by recorded decision and are not coming back
before this ships. **A step that seems to require one of them is a wrong step — stop and
ask.**

**No runtime AI-model calls in the shipped game.** The Vanguard is deterministic authored
Blueprint logic. Generative tools are for offline authoring only.

## Rules that bind every session

- **Never commit Blueprint or Unreal binary assets.** No `.uasset`, no `.umap`, no
  `Content/` binaries, in any commit an agent makes. They are LFS-tracked binaries git
  cannot merge, and a bad merge silently loses a side. Commit code, docs, config and
  scripts only. **If assets need committing, the user does it by hand.** Staging a
  `.uasset` is a broken rule, not a judgement call.
- **PowerShell, not Git Bash.** Git Bash rewrites Unreal `/Game/` paths.
- **One editor at a time.** The MCP binds `127.0.0.1:8000`; the port has one owner.
- **Checkpoint before touching approved geometry** — duplicate the level into
  `/Game/AscendantImpact/Maps/Checkpoints/`.
- **Every number is provisional** until the user plays it. Propose values; never settle
  one. A value left open is correct, not a gap to fill.
- **One step at a time, verified.** Never a one-shot build. A step is done when its
  "Done when" line is actually observed — never on "should work".

## Starting a session — the order is load-bearing

`START-HERE.md` has the full version. The short form:

1. Open `game/AscendantImpact.uproject`, let it finish loading.
2. In the editor Output Log `Cmd` box, type `ModelContextProtocol.StartServer`.
   **Never enable `bAutoStartServer`** — it makes the cook fail (`ExitCode=25`), and
   packaging is the gate that decides the grade.
3. Run `pwsh -File start-session.ps1`. Fix anything it flags.
4. **Only then** open the session. Claude Code attaches MCP servers at session start; a
   session opened before port 8000 is listening never sees the editor tools and cannot be
   repaired without quitting.

`/jump-on` runs steps 3–4 and reports. `/wrap-up` closes a session out.

## Unreal MCP — the traps that have each cost hours

- **Tool search is on**, so `tools/list` returns only `list_toolsets`,
  `describe_toolset`, `call_tool`. Every real editor tool goes through `call_tool`.
- **MCP payload scripts define `run()` and must be made to call it**, or they silently
  no-op and look like success.
- **`NameError` on `execute_tool` under plain `python` is expected** — those scripts run
  only inside the editor. Do not "fix" it.
- **PIE advances in real time between MCP calls.** The Vanguard keeps striking an idle
  player while you deliberate; a player can be knocked out between two tool calls. Re-read
  health and flags at every step, and restart PIE for clean phases.
- **Compiling a Blueprint mid-PIE kills Slate-injected input** for the rest of that
  session. Restart PIE after any mid-session compile before trusting an input test.
- **Agent-driven player input does not work here.** Three routes were tried and all
  failed. Anything needing a real key press is a human step — ask the user to press it.
- **A move that returns `False` for no visible reason is a suppressed modal.** Grep the
  editor log for `Message dialog closed`.
- **Do not enable plugins with Runtime modules.** There is no C++ toolchain; the project
  packages only because it is genuinely Blueprint-only. `GameplayStateTree` broke this
  once and is disabled.
- **`ObjectTools`: always `list_properties` before `get`/`set`.** Property names cannot be
  guessed and wrong ones fail silently.
- **Actors placed before a component was added to their Blueprint keep a frozen snapshot**
  that overrides `set_properties`. Delete and re-place the instance.
- Deeper detail lives in `game/docs/agent/PROTOTYPE_BLACKBOARD.md`.
